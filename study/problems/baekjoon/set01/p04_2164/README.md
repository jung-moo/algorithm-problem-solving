# 백준 2164번 - 카드2

## 1. 문제

1부터 N까지 번호가 붙은 N장의 카드가 순서대로 놓여 있다. 1번 카드가 가장 위에 있고, N번 카드가 가장 아래에 있다.

카드가 한 장 남을 때까지 다음 동작을 반복한다.

1. 가장 위에 있는 카드를 버린다.
2. 그다음 가장 위에 있는 카드를 가장 아래로 옮긴다.

마지막에 남는 카드의 번호를 구한다.

**입력**
- 정수 N (1 ≤ N ≤ 500,000)

**출력**
- 마지막에 남는 카드의 번호

## 2. 풀이 방법

**큐(Queue)** 자료구조를 사용하여 카드의 제거와 이동을 구현했다.

### 2.1. 시간 복잡도

**O(N)**

- 초기 N장의 카드를 큐에 삽입: O(N)
- 카드가 한 장 남을 때까지 N-1회 반복: O(N)
- `offer()`, `poll()` 연산: 분할 상환 O(1)

\* **분할 상황 O(1):** 별 연산의 시간 복잡도가 항상 O(1)인 것은 아니지만, 여러 연산을 수행했을 때 전체 비용을 연산 횟수로 나누면 연산당 O(1)이 되는 것을 의미한다. 예를 들어 ArrayDeque는 일반적으로 데이터를 삽입할 때 O(1)이 걸리지만, 내부 배열의 용량이 부족하면 배열을 확장하고 기존 데이터를 복사해야 하므로 해당 연산은 O(N)이 걸릴 수 있습니다.
하지만 배열 확장은 매번 발생하지 않고 드물게 발생하기 때문에, N번의 삽입 연산에 드는 전체 비용은 O(N)이고, 이를 연산당으로 환산하면 분할 상환 O(1)이 됩니다.

따라서 전체 시간 복잡도는 **O(N)**이다.

### 2.2. 공간 복잡도

**O(N)**

- N장의 카드를 저장하기 위한 큐가 필요하다.
- 입력 크기 N에 비례하여 메모리를 사용하므로 **O(N)**이다.

### 2.3. ArrayDeque를 사용한 이유

LinkedList 대신 ArrayDeque를 사용했다.

- 메모리 효율: 노드별 포인터를 저장하지 않아 메모리 오버헤드가 적다.
- 캐시 효율: 배열 기반으로 데이터를 저장하여 메모리 접근의 지역성이 좋다.
- 연산 성능: offer(), poll()을 효율적으로 처리하며, 일반적으로 큐 용도에서 LinkedList보다 성능이 좋다.
