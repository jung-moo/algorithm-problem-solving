# 순환 배열 (Circular Array)

## 1. 개념

**순환 배열(Circular Array)**은 배열의 마지막 인덱스 다음을 다시 첫 번째 인덱스로 연결된 것처럼 취급하는 방식이다.

실제로 배열의 양 끝이 연결되는 것은 아니며, **인덱스를 순환시키는 방식**으로 구현한다.

이를 활용하면 배열의 앞쪽에서 요소를 제거하더라도 나머지 요소를 한 칸씩 이동시킬 필요가 없다.

## 2. 동작 원리

큐를 순환 배열로 구현할 때는 보통 다음 두 인덱스를 관리한다.

- `head`: 다음에 꺼낼 요소의 위치
- `tail`: 다음에 추가할 요소의 위치

배열 길이가 5일 때 다음 인덱스를 구하는 식은 아래와 같다.

```java
nextIndex = (currentIndex + 1) % 5;
```

예를 들어 현재 인덱스가 `4`라면 다음 인덱스는 `(4 + 1) % 5 = 0`이 된다.

### 2.1. 요소 제거 (`poll`)

초기 상태:

```text
인덱스   0   1   2   3   4
배열    [1] [2] [3] [4] [ ]
         ↑               ↑
       head             tail
```

첫 번째 요소 `1`을 제거하면 다음과 같이 바뀐다.

```text
인덱스   0   1   2   3   4
배열    [ ] [2] [3] [4] [ ]
             ↑           ↑
           head         tail
```

`head`를 다음 인덱스로 이동시키므로 **기존 요소 `2`, `3`, `4`는 이동하지 않는다.**

### 2.2. 요소 추가 (`offer`)

위 상태에서 `5`를 추가하면 다음과 같다.

```text
인덱스   0   1   2   3   4
배열    [ ] [2] [3] [4] [5]
             ↑
           head
         tail → 0 (다음 삽입 위치)
```

`tail`이 배열의 끝에 도달했으므로 다음 위치는 `0`으로 돌아간다. 빈 공간이 있는 상태에서 `6`을 추가하면 다음과 같다.

```text
인덱스   0   1   2   3   4
배열    [6] [2] [3] [4] [5]
             ↑
           head
```

이때 배열에 저장된 순서와 **큐에서 꺼내는 논리적 순서**는 다르다. 논리적 순서는 `2 → 3 → 4 → 5 → 6`이다.

> 위 예시는 순환 인덱스의 원리를 보여주기 위한 단순화된 그림이다. 실제 구현은 `head`, `tail`이 같을 때 빈 상태와 가득 찬 상태를 구분하기 위해 크기 변수를 두거나 한 칸을 비워 두거나, 배열을 확장하는 등의 방법을 사용한다.

## 3. 시간 복잡도

| 연산 | 시간 복잡도 | 이유 |
|---|---|---|
| 맨 앞 요소 조회 (`peek`) | O(1) | `head` 위치를 조회 |
| 맨 앞 요소 제거 (`poll`) | O(1) | `head`를 이동 |
| 맨 뒤 요소 추가 (`offer`) | 보통 O(1) | `tail` 위치에 저장한 후 이동 |

고정 크기의 순환 배열은 빈 공간이 있다는 전제에서 삽입도 O(1)이다.

**크기가 늘어나는 동적 순환 배열**은 확장 시 기존 요소를 새 배열로 복사해야 하므로 한 번의 `offer()`가 O(N)이 될 수 있다. 그러나 배열 용량을 일정 비율로 증가시키면 삽입의 **분할 상환 시간 복잡도는 O(1)**이다.

## 4. 일반 배열 방식과 비교

| 구분 | 앞 요소 제거 시 동작 | 시간 복잡도 |
|---|---|---|
| 요소를 앞으로 당기는 배열 구현 | 남은 요소를 한 칸씩 이동 | O(N) |
| 순환 배열을 이용한 큐 | `head`만 다음 위치로 이동 | O(1) |

즉, **배열을 사용한다는 이유만으로 앞 요소 제거에 O(N)이 필요한 것은 아니다.** 인덱스로 유효 구간을 관리하면 요소 이동을 생략할 수 있다.

## 5. Java의 ArrayDeque와 관계

Java의 `ArrayDeque`는 **순환 배열 기반의 덱(Deque)**이다.

- `offer()`: 뒤쪽에 요소를 추가한다.
- `poll()`: 앞쪽 요소를 제거한다.
- `peek()`: 앞쪽 요소를 조회한다.
- 양 끝의 인덱스를 관리하므로 일반적인 삽입·삭제에서 요소 전체를 밀지 않는다.
- 내부 배열이 부족해지면 배열을 확장하고 요소를 복사할 수 있다.

따라서 `LinkedList`와 마찬가지로 큐의 양 끝 연산을 효율적으로 수행하면서도, **요소마다 별도의 노드 객체를 만들지 않는다는 장점**이 있다.

## 6. 핵심 정리

**순환 배열은 배열의 마지막 다음을 처음으로 취급하도록 인덱스를 순환시키는 구조다.**

큐에서 `head`와 `tail`을 이동시키는 방식으로 요소를 관리하므로 삽입·삭제 때 기존 요소를 한 칸씩 옮길 필요가 없다. 이 원리를 Java의 `ArrayDeque`에서도 활용한다.
